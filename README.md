# TACTIC — CS2 战术指挥室

一个面向五人车队的中文实时战术网站：暂停时由指挥画路线、放道具、分配经济与任务，队友通过同一个链接实时查看。

**不是静态演示**：具有真正的服务端共享房间、实时事件流、只读队友权限、冲突保护和磁盘持久化。前端是原生 ES Modules + SVG，后端使用 Node.js 内置模块，运行时不需要 npm 依赖、数据库账号或第三方云服务。

## 1. 快速启动

需要 **Node.js 20+**。

### 当前 Mac

双击 [启动战术室.command](<启动战术室.command>)。脚本优先使用系统 Node.js；没有时尝试使用已安装的 DeepSeek Harness Node 运行时。保持终端窗口打开，按 `Ctrl+C` 停止服务。

### 通用命令

在项目目录执行：

```bash
node server.mjs
# 或 npm start
```

浏览器访问 **http://localhost:3000**。程序还会在终端输出当前机器的局域网访问地址。

端口被占用时：

```bash
PORT=3001 node server.mjs
```

默认监听 `0.0.0.0:3000`，允许同局域网设备访问。只想自己使用时：

```bash
HOST=127.0.0.1 node server.mjs
```

## 2. 如何和队友一起用

1. 指挥先通过 **局域网 IP 或公网域名** 打开网站。例如 `http://192.168.1.20:3000`，不要使用 `localhost` 创建要发给其他设备的链接。
2. 选择预设，或者新建空白战术。选地图、T/CT 方，按队员颜色画路线和道具，填写每个人的经济、武器和任务。
3. 点击右上角 **创建共享房间**，复制队友邀请链接。链接形如 `http://服务器地址:3000/?room=ABC234`。
4. 队友无需注册，打开链接即可查看。指挥继续编辑，地图、当前阶段、经济和分工实时同步。
5. 指挥的编辑密钥仅保存在创建房间的浏览器 LocalStorage 中，不出现在邀请链接里。同一浏览器刷新后仍可继续指挥；其他浏览器默认只读。

**重要网络限制：**
- `localhost` / `127.0.0.1` 只能被当前机器访问，不能发给异地队友。
- 同一 Wi-Fi / 局域网：分享终端打印的局域网 IP，必要时允许系统防火墙的 Node 入站连接。
- 不同网络：需要把这个 Node 服务部署到可公网访问的服务器，或使用可信的网络隧道；本项目没有替你创建公网域名或云服务器。
- 指挥必须一直通过同一个来源（协议 + 域名/IP + 端口）访问。浏览器存储按来源隔离；从 `localhost` 换到 IP 后，不会自动拥有原房间的指挥权限。
- 在线人数是连接页面数量，包含指挥自己及重复打开的窗口，不是实名去重队员数。

## 3. 已实现功能

### 地图战术板
- 内置 **Mirage / 荒漠迷城、Inferno / 炼狱小镇、Dust II / 炙热沙城 II** 的本地 CS2 雷达图。
- 选择/拖动、进攻箭头、自由画笔、烟雾弹、闪光弹、燃烧弹、高爆手雷、五人位置、文字标注、橡皮擦。
- 每人一种颜色。数字 `1–5` 可以快速选人并切换为放置队员。
- 滚轮/按钮缩放；空格拖动或手掌工具平移；支持手机上的手掌工具拖动。
- 撤销/重做、当前阶段清空、专注模式。
- 上传不超过 3MB 的 PNG/JPG/WebP 雷达图。图片随房间同步，不依赖外链；建议使用正方形图片。

### 五人经济与分工
- 可编辑队员名字、定位、当前金钱、主武器、计划携带的道具和本局任务。
- 自动合计团队经济，支持全起/强起/经济局标记和回合号。
- 经济、武器、道具均为**手动战术计划**，不读取 CS2 客户端数据，不与游戏进程交互。
- 道具开关表示计划携带种类，不是实际游戏库存或精确购买模拟器。

### 战术预设与时序
- 三份有地图标记与五人分工的内置多阶段进攻战术。
- 自定义执行阶段，每阶段独立地图标记，点击切换，双击重命名。
- 保存、调用、删除本浏览器的自定义预设。
- 战术 JSON 导入/导出，可用于跨设备迁移与备份。
- 本地草稿在编辑时自动保存；共享房间会持久化到服务端磁盘。

## 4. 数据和权限边界

| 数据 | 存放位置 | 注意事项 |
| --- | --- | --- |
| 本地草稿 | 浏览器 LocalStorage | 清理浏览器站点数据会丢失 |
| 自定义预设 | 浏览器 LocalStorage | 不自动在设备间同步；建议导出备份 |
| 房间当前战术和编辑密钥 | 服务端 `data/rooms.json` | 运行时创建；请备份磁盘，不要提交到 Git 或公开下载 |
| 当前浏览器的房间编辑密钥 | 浏览器 LocalStorage | 清理后不能恢复原房间指挥身份；导出的战术 JSON **不包含编辑密钥** |

- 队友邀请链接提供只读权限；拥有链接的人都能查看，不适合存放隐私或敏感信息。房间不是带用户账号的私密聊天室。
- 写入需要随机 256 位 bearer 密钥，服务端强制验证，不依赖前端隐藏按钮。
- 多个指挥标签页使用乐观版本控制。冲突时载入已提交的更新并提示，不静默覆盖别人的新布置。
- 当前实现是**单进程、小队自托管版本**，默认最多 500 个房间，不自动过期、删除或进行账号管理。公开大规模运营前需增加认证、房间生命周期、监控、限流与数据库。
- 数据持久化使用串行事务与临时文件原子替换。磁盘写入失败不会被当作成功同步。备份时建议先停止服务，完整复制数据目录。
- 不要用多个进程同时写同一数据目录；共享盘/无持久卷的临时托管环境也不适用。
- 目前编辑密钥没有自助转让或找回。要更换指挥设备，请导出战术，在新设备导入并创建新房间。

## 6. Docker / 公网部署

附带 [Dockerfile](<Dockerfile>) 与 [Compose 配置](<compose.yaml>)，生产镜像不安装开发测试依赖。

```bash
docker compose up -d --build
```

默认映射 `3000:3000`，房间数据保存在命名卷 `tactic-data`。更改宿主机端口：

```bash
TACTIC_PORT=8080 docker compose up -d --build
```

公网建议在前面使用 Caddy / Nginx 配置 **HTTPS**。下面是 Nginx 反向代理的关键部分（域名、证书和防火墙需自行配置）：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 120s;
    client_max_body_size 7m;
}
```

实时同步使用 **Server-Sent Events（SSE）**。代理必须关闭缓冲，并允许长连接；静态文件托管（只有 HTML/CSS 的空间）不能运行房间服务。请将整个应用部署在站点根路径。

注意：容器配置已提供，但本机验证使用原生 Node，未在本机运行 Docker 镜像构建。

## 7. 测试

服务端和战术数据测试没有第三方依赖：

```bash
npm test
npm run check
```

真实浏览器端到端测试使用 Playwright：

```bash
npm install
npx playwright install chromium
npm run test:e2e
```

在已安装 Google Chrome 的 Mac 上，配置会优先使用系统 Chrome；其他平台使用 Playwright Chromium。浏览器测试会在隔离的 `127.0.0.1:3100` 启动测试服务，测试数据放在忽略提交的 `test-results/` 下，不修改真实共享房间。

已覆盖：服务端鉴权、SSE/人数/断线、冲突与并发写入、重启持久化、路径安全、请求大小、战术数据边界，以及桌面绘图、拖动、撤销/重做、阶段编辑、预设、导入/导出、两浏览器实时同步、队友只读、手机布局、自定义地图和异常恢复。
